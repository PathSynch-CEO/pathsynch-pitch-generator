1. Settings: per-star policy

Desktop table; mobile stacks into cards
Implementation spec
Location PathManager Settings > Notifications tab, replaces existing 4-5 star boolean toggles
Component Create src/components/settings/AutoReplySettings.jsx (or .tsx, match project convention)
Data source Auto-reply settings object stored in merchant document or dedicated collection. Read via GET /api/v1/reviews/auto-reply-settings
Write endpoint PUT /api/v1/reviews/auto-reply-settings -- tier-gated on backend. Rejects mode changes that exceed plan entitlements.
Tier gating Use normalizePlanTier() / meetsMinTier() from planTierUtils.ts. Growth/Scale: 1-2 star locked to "Draft only on this plan" (disabled select). Agency: all modes available after acknowledgment.
Data migration Existing boolean toggles for 4-star and 5-star auto-reply must migrate to the new starSettings object. Write a one-time migration script: { "5": { mode: "auto_reply", delayHours: 4 }, "4": { mode: currentToggleState ? "auto_reply" : "off", delayHours: 4 } }
Safety column Green dot = auto-post allowed (4-5 star). Amber dot = approval recommended (3-star) or contact path required (2-star). Red dot = highest sensitivity (1-star). These are display-only indicators, not toggles.
Policy summary Dynamically generated from current starSettings. Not hardcoded text. Rebuild on any settings change before save.
Dirty state Track unsaved changes. Show "Unsaved changes: {description}" footer. "Save changes" button calls PUT /api/v1/reviews/auto-reply-settings.
Feature flag REVIEW_AUTOREPLY_3STAR_ENABLED (PR #4), REVIEW_AUTOREPLY_NEGATIVE_DRAFTS_ENABLED (PR #5). If flag is off, rows for that star band are hidden entirely.
Disabled tooltip When mode selector shows "Draft only on this plan" (disabled state), hovering displays tooltip: "Upgrade to Agency to enable automatic posting for 1-2 star reviews." On mobile, tapping the disabled select shows an inline upgrade prompt below the row.
Mobile layout On viewports below 800px, the four-column table collapses into stacked cards: one card per star band showing rating, mode selector, delay selector, and safety status vertically. The table header row is hidden. Settings table uses grid-template-columns: 1fr on mobile.

Safety override: Draft-only mode

When enabled, every AI-generated reply is held for approval before posting. Use during review surges, sensitive incidents, or whenever you want to pause automatic posting.

2. Contact path prerequisite

Blocks 1-2 star replies until a resolution path exists
Implementation spec
Location Same settings panel as Mockup 1. This state replaces the 1-2 star rows when no contact info is configured.
Data check Query merchant MongoDB document for manager_email, manager_phone, or contact_url fields. These may be in the Knowledge Box subdocument -- inspect during Phase 0 (PR #1).
Lock logic If zero of three contact fields are populated: dim 1-2 star rows (opacity 0.42, pointer-events none), show lock card below. If at least one is populated: unlock rows, show green check items for populated fields.
Partial state If 1 of 3 fields is populated, the lock lifts. The check grid shows green checks for populated fields and red X for missing ones. Missing fields are informational, not blocking.
Link target "Add contact path in Knowledge Box" button navigates to PathManager Settings > Knowledge Box tab (or the relevant section where merchant contact info is configured).
Auto-unlock "Once saved, 1-2 star draft mode will unlock automatically" -- on return to Notifications tab, re-check contact fields. No page refresh required if using reactive state.

3. Pending replies approval queue

Reviews tab
Implementation spec
Location PathManager Reviews page. Add "Pending replies" as a new tab/filter alongside existing "All reviews," "Unanswered," "Replied."
Component Create src/components/reviews/PendingRepliesQueue.jsx. Each card is a PendingReplyCard.jsx subcomponent.
Data source Persistence layer: TBD in Phase 0. Default recommendation: keep in PathManager backend/MongoDB unless Phase 0 confirms Firestore is already used for review real-time state. Query: tenantId == req.user.sub AND status == "pending", ordered by generatedAt DESC. SynchNotify remains event-only -- it does not own pending reply data.
List endpoint GET /api/v1/reviews/pending-replies -- returns array of pending drafts. Supports ?status=pending&starRating=1 filters.
Post action POST /api/v1/reviews/pending-replies/:id/post -- validates all 7 cancellation rules, then calls existing GBP reply endpoint POST /reviews/gmb/reviews:reply. Updates pendingReplies status to "posted". Emits review_auto_reply_posted to SynchNotify.
Edit action PUT /api/v1/reviews/pending-replies/:id/edit -- updates editedReply field. Does not post. Merchant clicks "Post" after editing.
Dismiss action POST /api/v1/reviews/pending-replies/:id/dismiss -- sets status to "dismissed", sets dismissedAt. Draft no longer appears in queue.
Badge count The red badge on the "Pending replies" tab shows count of drafts where status == "pending". Update mechanism depends on persistence layer decision (polling if MongoDB, real-time listener if Firestore).
Risk styling Low risk: blue draft box (#EFF6FF bg, #B9CCF9 border), green badge. Medium risk: same blue box, amber badge. High risk: red draft box (#FFF7F7 bg, #F0A3A3 border), red badge, "Review & edit" as primary action instead of "Post reply".
Chips Derived from Gemini output contract: usedKnowledgeBaseFields array maps to green chips ("Used brand voice", "Used FAQ"). riskLevel maps to risk badge. Special detections (billing dispute, service failure) from reason field map to red chips.
Details panel Collapsible <details> element. Shows model name, confidence score, prompt template version. Auto-open for high-risk drafts ("Why flagged?" summary). Data from pendingReplies document fields.
Expiration Calculate from expiresAt - now(). Display as "Expires in {N}h". When expired, a scheduled function sets status to "expired". Expired drafts disappear from the queue.
Empty state Show dashed-border card with "No pending replies" message when query returns zero results.
Feature flag REVIEW_PENDING_REPLIES_UI_ENABLED (PR #6). If off, the "Pending replies" tab is hidden entirely.
Action states Each action button (Post, Edit, Dismiss, Flag) needs three states: (1) default, (2) loading ("Posting to Google..." with spinner, button disabled), (3) success ("Posted successfully" with green check, card fades out after 2s), (4) failed ("Failed to post -- retry?" with red text and retry button). Never leave a card in an ambiguous state after an action.
Post without edits The danger-styled "Post without edits" button on high-risk cards triggers a confirmation modal: "This reply was flagged as high risk. Posting without edits may affect your public reputation. Are you sure you want to publish it to Google?" with "Cancel" and "Publish to Google" (danger-styled) buttons.

4. Agency acknowledgment modal

Required before fully automatic 1-2 star posting
Implementation spec
Trigger Agency-tier merchant changes mode for 1-star or 2-star from "Draft for approval" to "Auto-reply" in the settings table (Mockup 1). Modal appears before the change is saved.
Component Create src/components/settings/NegativeReplyAcknowledgmentModal.jsx. Rendered as a portal/overlay.
Checkbox state "Enable automatic replies" button is disabled (opacity 0.48, cursor not-allowed) until checkbox is checked. Use a real <input type="checkbox"> with an associated <label> for accessibility -- not a styled div. The checkbox must be keyboard-focusable and screen-reader-announced. Use local React state, not a form submission.
On confirm Sets negativeReviewAutoReplyAcknowledged: true in auto-reply settings. This is a one-time acknowledgment -- modal does not appear again unless merchant disables and re-enables full auto for negative reviews.
Contact check The "Contact path verification" section in the modal re-verifies that contact fields are still populated. If they've been removed since the lock was lifted, the modal shows red X items and the "Enable" button remains disabled even with checkbox checked.
On cancel Close modal. Revert the mode selector back to "Draft for approval". No settings change.
Feature flag REVIEW_AUTOREPLY_NEGATIVE_AUTOPOST_ENABLED (PR #8). If off, the "Auto-reply" option does not appear in the mode selector for 1-2 star rows, even on Agency tier.
Legal text The acknowledgment copy in the checkbox area is the canonical text. Do not modify without product/legal review. The sentence about "high-risk replies will still require review" is a hard guarantee enforced by the Gemini output contract (riskLevel: "high" forces draft regardless of settings).
